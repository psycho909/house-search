# UI / UX Design — 比較清單方向

狀態：設計基準；首頁 fixture UI 已依本文件實作搜尋、篩選與結果狀態，本票的瀏覽器手測仍待完成。本文件承接 [PROJECT.md](../PROJECT.md) 與 [SPEC.md](../SPEC.md)；來源使用邊界以 [SOURCE-FEASIBILITY.md](SOURCE-FEASIBILITY.md) 為準。

## 1. 方向與設計判準

使用者的工作是**在同一組條件下比較不同網站的候選房源**。首頁的主角是可操作的搜尋，不用大型情境照、行銷標語或地圖；結果主角是能一眼比較的價格、建坪、格局、地區和來源。特徵元素為「房源對照列」：桌面每筆資料共享欄位基線，手機保留相同優先順序但改為單欄，不讓圖片或裝飾打斷比較。

現有草案已有欄位與錯誤狀態，但尚未定義對齊、條件套用時機、資訊真實性層級及無圖時的版面。這次補足這些決策。色系以暖石灰、深棗紅與胡桃色為主，呼應房屋材質和契約印記；避免通用房產商城卡片牆、米色大襯線首頁、漸層與每張卡同尺寸陰影。視覺記憶點只放在清晰的價格／坪數對照列，其他部分保持安靜。

## 2. 設計 token（實作前須用實際字型與裝置複核）

| Token | 值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F1EBE7` | 暖石灰底色，襯托房源資料 |
| `ink` | `#302826` | 深胡桃色，用於標題、價格與主要內容 |
| `muted` | `#685750` | 暖灰褐，用於補充資訊與欄位說明 |
| `rule` | `#968075` | 石棕色，用於行分隔與表單邊界 |
| `action` | `#6E3B49` | 深棗紅，用於搜尋按鈕、焦點與來源連結 |
| `caution` | `#9A421F` | 深赭色，用於來源失敗與驗證錯誤；不只靠顏色傳達 |

列表表面用偏暖白 `#FCFAF8`，不用多層背景或陰影。初步計算：`ink`／`canvas` 約 12.20:1、`muted`／`canvas` 約 5.79:1、白字／`action` 約 8.81:1、`rule`／暖白表面約 3.58:1；需在實作後複查字級、透明度及 hover／disabled 狀態。棗紅只標示操作與焦點，不用來暗示房價好壞；來源成功、失敗與未啟用均用文字，不用單一色點。

字型建議：中文介面使用 **Noto Sans TC**（可在產品實作時評估載入成本與授權）作為主要字體；金額與數字使用 **IBM Plex Sans** 的 tabular numerals，fallback 為系統 sans-serif。金額字型是資訊工具，不是裝飾；若字型載入影響速度，先保留字級與 tabular 對齊。基準內文 16px／行高 1.55；主要標題 28–32px；結果金額 24–28px；輔助資訊不低於 14px。中文長文案行寬約 28–36 個全形字；主要內容左對齊，金額欄右對齊。禁用全大寫英文字標籤、無意義的編號和僅為裝飾的額外眉標。

間距以 4px 為基礎：欄內 8／12px、區塊 16／24px、桌面大區塊 32px。分隔線表示資料列或群組邊界；圓角只用於可操作控制與手機抽屜（約 8px），不把所有內容包成同款卡片。狀態變化以內容更新與焦點處理回應操作；沒有自動進場動畫，遵守 reduced motion。

## 3. 版面與資訊層級

### Desktop（約 1024px 以上）

內容最大寬度提案 1180px，靠左對齊於置中的內容容器。搜尋列置頂；結果區使用一條窄的條件欄與寬的房源比較欄。若條件欄影響房源可讀寬度，改為上方橫向條件區，不能縮小字體補救。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 跨站找房                         來源說明                                  │
│ 新北市 [選擇]  新莊區 [選擇]  關鍵字 [選填]              [搜尋房源]       │
│ [總價] [坪數] [格局] [更多條件]   已套用：新莊區 ×  20–40 坪 ×          │
├────────────────────────────────────────────────────────────────────────────┤
│ 本次取得且符合條件：27 筆  ·  591 18｜永慶 9｜信義暫無法取得            │
│ 結果僅涵蓋本次成功取得的來源                              [來源狀態詳情] │
├────────────────────────────────────────────────────────────────────────────┤
│ 物件／位置                    坪數・格局       屋齡       總價／單價    │
│ ○ 中港路三房車位             32.5 坪・3房     18 年      1,580 萬      │
│   新北市新莊區 · 永慶         車位已提供       資料來源   48.6 萬/坪    │
│   [查看原站物件]                                                     │
├────────────────────────────────────────────────────────────────────────────┤
│ ○ 社區另一筆刊登...           ...              ...        ...           │
└────────────────────────────────────────────────────────────────────────────┘
```

圖中數字與物件名稱只是**合成示意**，不可作為 fixture 的真實來源資料。無授權圖片時，不預留空白大圖框；以簡單的房屋類型符號或純文字列起始。物件標題單行不足時可到兩行，價格仍在固定欄位。金額與單價有不同字級；不要用字色把較低價格暗示成「較好」。地區與社區只能顯示來源提供的部分。

### Tablet（約 600–1023px）

搜尋區兩列；結果列保留物件資訊與右側價格，坪數、格局、屋齡在第二行。篩選集中成可展開區塊，已套用條件仍出現在結果前。以內容是否擁擠決定切換點，而非只依裝置名稱。

### Mobile（320–599px）

單欄搜尋；「更多條件」開啟底部抽屜。結果每筆先看總價，再看標題、地區、建坪／格局、來源與外連；單價與屋齡在次要行，不因圖片缺失而產生空位。

```text
┌──────────────────────────────┐
│ 跨站找房                     │
│ 縣市 [新北市]                │
│ 行政區 [新莊區]              │
│ 關鍵字 [選填]                │
│ [更多條件 2]  [搜尋房源]     │
│ 已套用：20–40 坪 × ...       │
│ 27 筆｜部分來源未取得        │
├──────────────────────────────┤
│ 1,580 萬                    │
│ 中港路三房車位              │
│ 新莊區 · 32.5 坪 · 3 房      │
│ 48.6 萬/坪 · 永慶            │
│ [查看原站物件]               │
└──────────────────────────────┘
```

手機不把底部搜尋按鈕永久覆蓋結果；抽屜中的「套用條件」在鍵盤開啟時仍可見或可捲到。觸控目標設計值至少 44×44 CSS px，焦點框可見；實作驗收至少符合 WCAG 2.2 目標大小規定及鍵盤操作。抽屜開啟時焦點移入，關閉後回到觸發按鈕，Esc 可關閉。

目前頁面在 600px 以下把額外篩選放入底部抽屜；縣市、行政區、關鍵字與搜尋按鈕留在頁面上。開啟時焦點移到關閉按鈕，Tab 焦點留在抽屜內；Esc 或「完成設定」會關閉並把焦點還給觸發按鈕。600px 起篩選維持頁面內顯示。

## 4. 搜尋與篩選互動

1. 縣市與行政區在搜尋前必填；行政區選項依縣市更新，改縣市即清除原行政區。欄位錯誤貼近欄位顯示，焦點移至第一個錯誤。
2. 關鍵字 placeholder 用「社區、路名或物件名稱」，不預設「鴻運及第」讓人誤以為已填。輸入時不發出來源請求；明確按「搜尋房源」才開始查詢。
3. 總價（萬元）、單價（萬元／坪）、建坪（坪）皆有上下限，明示「不限」與範圍包含端點。更多條件含房數、屋齡、類型、車位；類型字典待資料契約確認，不先編造來源選項。
4. 篩選抽屜中的編輯為草稿；按「完成設定」關閉抽屜並更新搜尋表單，**不自動再次請求來源**。若表單條件相對上次結果已變更，結果上方提示「條件已變更，請重新搜尋」，並把原結果標為「上次搜尋結果」；搜尋鍵仍顯示「搜尋房源」。
5. 表單附近的具名 chip 顯示「待搜尋條件」，移除 chip 只改草稿；結果摘要另以文字顯示「本次結果使用的條件」，直到再次搜尋成功才同步。可用「清除其他條件」保留必填的縣市／行政區，避免無效查詢。成功搜尋後兩處條件一致，結果附近的摘要供確認。

**設計取捨：** 主動搜尋符合低頻來源策略，但比即時篩選多一次點擊；用「待搜尋條件／上次搜尋結果」兩種標示避免舊結果冒充新查詢。未來若來源許可或架構允許，才評估只對已取得候選執行本地篩選的即時模式，須另驗證結果完整性。

## 5. 結果列資料規則

| 資訊 | 顯示方式 | 缺值／不確定 |
| --- | --- | --- |
| 總價 | 最醒目，單位「萬」；數字 tabular 對齊 | 「價格未提供」，不得顯示 0 萬 |
| 單價 | 次要欄，明示「萬／坪」 | 不由總價與建坪自行推算 |
| 坪數 | 用「建坪」或來源已證實的面積定義 | 未知顯示「坪數未提供」 |
| 格局／屋齡／車位 | 只顯示來源確定值，房數可讀為「3 房」 | 車位缺值不得顯示「無車位」 |
| 地點／社區 | 按 city → district → community／address 漸進呈現 | 只顯示已知層級，不推測門牌 |
| 來源／時間 | 來源名稱與「查看原站物件」固定可見；可信日期才顯示 | 無日期時省略，不顯示「剛更新」 |
| 圖片 | 僅在授權允許且有可靠 URL 時顯示 | 無圖版面仍完整，不以原站截圖替代 |

結果筆數標示「本次取得且符合條件的 Listing」，不是市場總量。疑似同一房屋的跨站刊登以「可能是同一房屋」附註並保留各來源列與價格；不把兩個物件合併成一張卡。同來源完全重複可去除。未知欄位導致篩選排除時，在摘要顯示「部分物件因資料不足未列入符合結果」，不要給出無根據的排除筆數。

## 6. 狀態、文案與行動

| 狀態 | 主文案 | 使用者可做的事 |
| --- | --- | --- |
| 初始 | 「選擇縣市與行政區，開始找房」 | 設定條件 |
| 搜尋中 | 「正在搜尋已啟用來源」 | 看見搜尋進度；避免重複送出 |
| 搜尋服務連線失敗 | 「無法連線至搜尋服務，請檢查網路後重試」 | 檢查連線後重試 |
| 搜尋服務逾時 | 「搜尋服務逾時，請稍後重試」 | 稍後重試 |
| 部分成功 | 「已取得部分來源的結果」 | 查看成功來源房源與失敗原因；再次搜尋 |
| 單來源失敗／逾時 | 「信義暫時無法取得」／「信義搜尋逾時」 | 保留其他來源結果；再次搜尋 |
| 所有來源失敗 | 「這次未能取得房源資料」 | 重新搜尋，不能顯示 0 筆房源 |
| 無符合結果 | 「這次取得的房源中沒有符合條件的物件」 | 放寬條件後重新搜尋 |
| 沒有啟用來源 | 「目前沒有可用的房源資料來源」 | 查看來源狀態；不能把官方網站連結標成搜尋結果 |
| 條件已改未搜尋 | 「條件已變更，請重新搜尋」；舊列表標「上次搜尋結果」 | 明確提交新查詢 |

來源狀態列用「591：成功取得 18 筆候選」「信義：暫時無法取得」「永慶：未啟用」等完整文字，避免只用綠／紅燈。筆數示例為合成示意。現行頁面以固定合成 fixture 顯示結果；591、信義與永慶仍標示未啟用，不呈現即時來源結果。錯誤不顯示內部 Request、HTML 或技術堆疊；必要時提供簡短原因。沒有啟用來源時，若提供「前往官方網站」，須明確標示為外部人工搜尋入口，不能偽裝成本站已搜尋。

## 7. 無障礙與內容驗收

- 在 320、375、768、1024、1440px 檢查：無水平捲動；價格／單位／來源不截斷；字級不縮小到難讀。這些是設計驗收寬度，不等於已做實機測試。
- 使用鍵盤完成必填、開關抽屜、移除 chip、搜尋、查看原站；焦點順序與畫面順序一致，關閉抽屜焦點返回。錯誤與來源狀態以文字宣告。
- 檢查正文、按鈕、次要文字及錯誤色的實際對比度與 focus 樣式；上述 token 初算不能替代成品檢測。測試 reduced motion、200% 縮放與長標題。
- 用合成 fixture 覆蓋：完整資料、無價格／無圖、無車位資訊、跨站疑似重複、單來源失敗、全部失敗、無啟用來源及條件改後未搜尋。文案逐一核對 `SPEC.md` 的資料真實性規則。
- 用 3 位目標買方做可用性走查的**後續建議**：在 2 分鐘內設定新北市／新莊區與預算，指出哪筆較便宜、來源是誰、是否有來源失敗；記錄錯誤與猶豫點，不以規劃文件宣稱已通過。
